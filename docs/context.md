## Кейс

Полный текст: `docs/case/case.pdf`, текстовая версия — `docs/case/case.txt`.

Коротко: на вход одно резюме и набор вакансий. На выход — рейтинг вакансий для кандидата и по каждой вакансии таблица «требование · подтверждение в резюме · статус · комментарий». Минимум четыре статуса (соответствует, частично, не соответствует, не указано). Плюс сильные стороны, пробелы и риски, рекомендация рекрутеру и вопросы кандидату. Выводы опираются только на текст документов.

Данные кейса — 4 резюме (ФИО вымышлены) и 3 вакансии из несвязанных областей. **Файлы данных в этом чате не передавались, только PDF с описанием.** Их нужно положить в `data/case/`; если папка пуста — попросить пользователя.

**Ограничение по данным** (дословно из кейса): «Через любые внешние API можно передавать только открытые (/не конфиденциальные) данные». И из сообщения пользователя: «доступом по API к LLM можно будет пользоваться, но без передачи конфиденциальной информации о пользователях, всё остальное должно быть защищено». Отсюда маскирование ПДн до вызова LLM, guard в клиенте и журнал исходящих запросов (T02, T03).

### Как оценивают

Таблица критериев — в `CLAUDE.md`. Пять выводов из полного текста кейса, которые определили план:

1. **Направление: одно резюме, много вакансий.** Балл должен быть сравним между вакансиями с разным числом требований.
2. **20 баллов из 100 — за Docker, README и описание архитектуры.** Самые дешёвые баллы, Docker поднимаем первым.
3. **41 балл (критерии 2, 4 и первый пункт 5) — за одно умение:** связать требование с фрагментом резюме и не выдумать вывод там, где фрагмента нет.
4. **Жюри, скорее всего, запустит решение на своих документах**: новые резюме и вакансии другой структуры, пустые и битые файлы, чистое окружение. Подгонка под три вакансии кейса стоит баллов (D12, `check-leak`).
5. **Три вакансии из разных областей** — никаких словарей и правил под одну отрасль.

## Окружение разработки

- Ноутбук **RedmiBook Pro 15, AMD Ryzen 7 7840HS**, встроенная графика Radeon 780M, **NVIDIA нет**. Windows, PyCharm.
- Всё, кроме LLM, работает на процессоре и укладывается в секунды: Natasha, BM25, эмбеддинги `multilingual-e5-small`. Обучения моделей в проекте нет.
- **LLM — только по API** (D20). Локальная модель 7–8B на этом процессоре даёт порядка 10 токенов в секунду. Полный холодный прогон кейса (4 резюме × 3 вакансии) — около 100 вызовов, ~300 тыс. входных и ~100 тыс. выходных токенов, то есть часы. Профиль `local` в Compose делаем, но проверяем на одной паре.
- В папке остались файлы от PyCharm: `.venv` на Python 3.14 и `main.py`-образец. uv пересоздаст `.venv` на 3.12, `main.py` удаляем в T00 (D19).
- Особенности Windows (make, переводы строк, кодировка) — в `CLAUDE.md`, раздел «Окружение».

| Провайдер | Плюсы | Что учесть |

Нужна модель с хорошим русским и structured output (JSON-схема или хотя бы JSON-режим). Цены пользователь проверит сам.
