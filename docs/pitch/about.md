# AIHR: подбор вакансии по доказательствам

Рекрутер МФТИ загружает резюме кандидата, а AIHR сравнивает его с открытыми вакансиями института и строит рейтинг с причиной места каждой вакансии. По каждой вакансии рекрутер получает таблицу «требование, цитата из резюме, статус, комментарий», сильные стороны, риски, вопросы кандидату и черновик письма. Нанимающий менеджер получает тот же отчёт в DOCX.

## Задача

По словам заказчика, рекрутер тратит 10–20 минут на сопоставление одного кандидата с несколькими вакансиями и ещё 10–15 минут на оформление. В пиковые дни приходит больше 300 откликов, отдельной ATS у института нет. AIHR считает одно резюме против трёх вакансий за 73–87 секунд.

## Доверие к ответам

Языковая модель у нас отвечает номером фрагмента резюме. Текст цитаты код берёт из исходного документа, поэтому модель не может придумать цитату. Если модель не нашла фрагмент, код ставит «Не указано». Этот статус рекрутер видит отдельно от «Не соответствует». К нему система добавляет вопрос кандидату и показывает балл интервалом от худшего случая до лучшего.

Стаж, пороги образования и языка, балл и рейтинг считает код по одной формуле для всех вакансий, веса лежат в открытом конфиге. Объяснение места каждой вакансии код собирает из чисел. Рекомендацию и письмо кандидату код проверяет: каждое число и название из текста должно найтись в документах.

Перед отправкой в модель мы заменяем ФИО, контакты, документы и дату рождения метками. Guard блокирует запрос, если в тексте осталось что-то личное, а каждый исходящий запрос рекрутер открывает в журнале.

## Цифры

Мы разметили вручную 200 требований для 12 пар «резюме и вакансия». На них AIHR показал:

- 86% статусов совпали с ручной разметкой;
- 0 ложных «Не соответствует»;
- 447 цитат из 447 нашлись в резюме дословно;
- 96% требований вакансий извлечены.

Та же модель с одним промптом дала 5 ложных «Не соответствует», и только 70% её цитат совпали с резюме. Чтобы проверить себя на подгонку, мы разметили вакансии и резюме других профессий до первого прогона. На них AIHR совпал с разметкой в 96% случаев. Слов из вакансий кейса в коде и промптах нет, это проверяет отдельный скрипт.

## Сверх кейса

- **Реестр открытых вакансий.** Рекрутер один раз добавляет вакансию файлом или ссылкой на hh.ru и дальше загружает только резюме.
- **Пакет до 50 резюме.** Матрица «кандидат × вакансия» показывает лучших кандидатов на каждую вакансию, это закрывает входящий поток откликов.
- **«Что если».** Кандидат ответил на вопрос, рекрутер отмечает ответ, код пересчитывает балл без модели.
- **Проверка вакансии.** Система находит требования, которые резюме не подтвердит, и формулировки, похожие на дискриминацию.
- **Защита от скрытого текста.** Белый шрифт и фразы вроде «игнорируй инструкции» система вырезает из анализа и показывает рекрутеру.

## Запуск

Команда `docker compose up --build` поднимает API и интерфейс. Мы проверили запуск из чистого клона: сборка и старт заняли шесть минут, все три сценария из README прошли. Без ключа LLM AIHR работает на правилах и не отправляет данные наружу. Если институт не может пользоваться внешним API, администратор подключает локальную модель через профиль `local`.

Живую версию с LLM и презентацию вы найдёте по ссылкам в README.
