# T02. Персональные данные: маскирование, guard, журнал

**Владелец:** B · **Зависит от:** T01 · **Критерии:** ограничение кейса «во внешние API только открытые данные», доп. фича для защиты

## Цель

Во внешний API уходит только обезличенный текст, и это можно проверить по журналу. Маскирование применяется к резюме и к вакансиям (в вакансиях бывают контакты рекрутера).

## Шаги

### 1. Что маскируем

| Что | Как ловим | Замена |
|---|---|---|
| ФИО кандидата | имя файла, первые 3 строки, NER (Natasha, PER) в разделе `contacts` и в начале документа | `[CANDIDATE]` |
| Другие люди (рекомендатели, руководители) | NER PER | `[PERSON_1]`, `[PERSON_2]` … |
| Email | regex | `[EMAIL_1]` |
| Телефон | regex для российских и международных форматов | `[PHONE_1]` |
| Ссылки (соцсети, мессенджеры, портфолио) | regex: http(s), t.me, vk.com, @ник | `[URL_1]` |
| Дата рождения | regex рядом со словами «дата рождения», «родился», «д.р.» | `[BIRTHDATE]` |
| Возраст | «35 лет» рядом с «возраст» или в первых строках | `[AGE]` |
| Адрес | NER LOC + слова «ул.», «д.», «кв.», индекс | `[ADDRESS]` |
| Город проживания | NER LOC в разделе `contacts` | `[CITY]` |
| Паспорт, СНИЛС, ИНН | regex | `[ID_DOC]` |
| Пол, семейное положение, гражданство | ключевые фразы в `contacts` / `about` | удаляем фразу |

Работодатели и вузы не маскируем (D16). Слепой режим со скрытием и их — доп. фича позже.

### 2. Склонения ФИО

Фамилии склоняются: «Иванов», «Иванова», «Иванову». Для найденного ФИО строим шаблон по основе (фамилия без 1–2 последних букв + до 3 любых букв окончания) и заменяем все вхождения. То же для имени.

### 3. PrivacyContext

Таблица замен «токен → исходное значение» на один прогон. Живёт только в памяти. Никогда не пишется в логи, файлы и результат. `unmask(text, ctx)` возвращает исходные значения в текст отчёта, который показывается пользователю локально.

### 4. Guard

Вызывается внутри `llm/client.py` перед каждым запросом. Проверяет итоговый текст запроса:

- регулярки email, телефон, ссылки, документы;
- все исходные значения из `PrivacyContext` (ФИО и его основы).

Нашли — запрос **не отправляется**, бросается `PrivacyViolation`, в лог пишется событие без самих данных («найден email в промпте match_pass_a»). Шаг падает, пайплайн уходит в режим без LLM для этого вызова.

### 5. Журнал исходящих запросов

`data/runs/<run_id>/outbound.jsonl`, одна строка на запрос: время, `prompt_id`, модель, полный текст запроса (он уже обезличен), размер ответа, время ответа, был ли ответ из кэша. Эндпоинт `GET /runs/{run_id}/outbound`, вкладка в UI «Что ушло наружу».

## Тесты

- Синтетическое резюме со всеми типами ПДн → после маскирования ни одно исходное значение не находится в `masked_text`.
- Склонения: «Петрова Анна», «Петровой Анны», «Петровой А.» маскируются.
- Guard блокирует запрос, в который вручную подложен email.
- **Главный тест:** прогон на 4 резюме кейса → в `outbound.jsonl` нет ни одного ФИО, email, телефона, ссылки из исходных файлов. Этот тест упоминаем в README и на защите.
- Маскирование не ломает смысл: названия навыков, компаний, вузов и даты работы остаются.

## Критерии готовности

- [ ] Все тесты выше зелёные.
- [ ] Ни в одном лог-файле нет исходных ПДн (проверка grep по значениям из тестового резюме).
- [ ] В README раздел «Внешние сервисы и данные» описывает, что уходит наружу и как это проверить.
