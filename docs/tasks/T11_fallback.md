# T11. Режим без LLM

**Владелец:** B · **Зависит от:** T01, T05-B, T06-B, T08 · **Критерии:** 5 (надёжность), 6 (запуск без ключа)

## Цель

Система не падает, когда LLM недоступен: нет ключа (`LLM_PROVIDER=none`), нет сети, провайдер вернул ошибку после всех повторов. Результат беднее, но честный: та же структура `MatchResult`, `mode="fallback"`, предупреждение в UI.

Команда отметила режим как обязательный.

## Принцип

Без LLM система не ставит «Не соответствует», кроме случаев, когда это доказывает код (порог по стажу, уровень образования). Неуверенность → «Не указано». Лучше скромный результат, чем уверенная ошибка.

## Шаги

1. **Требования** (`extract_requirements_fallback`): каждый пункт списка в разделах `requirements`, `nice_to_have`, `duties` → требование. Модальность по маркерам и ролям разделов (те же правила, что в T04, шаг 2). Перечисления через запятую в пунктах с навыками режутся на атомарные требования, если элементы находятся в словаре синонимов. Пороги регулярками: «от N лет», «не менее N лет», «высшее», уровни языка.
2. **Профиль** (`extract_profile_fallback`): места работы из раздела `experience` по шаблону «даты + должность + организация», даты через `dates.py`. Навыки из раздела `skills` и словаря синонимов. Образование из раздела `education` по ключевым словам уровней.
3. **Сопоставление** (`match_vacancy_fallback`):
   - канонические термины требования найдены во фрагментах опыта → «Соответствует», прямое доказательство;
   - найдены только в списке навыков → «Соответствует», `listed_only`, вопрос;
   - найден навык того же класса → «Частично», смежное;
   - пороги — через `rules.py`, как в основном режиме;
   - иначе → «Не указано».
4. **Отчёт:** таблица, сильные стороны, пробелы, риски, вопросы — шаблонами (T09, шаги 1–5 без генерации). Рекомендация и письмо — только шаблоны.
5. **Переключение.** `pipeline.run` при `LLMUnavailable` на любом шаге переходит в режим без LLM для этого шага и пишет предупреждение. При `LLM_PROVIDER=none` — сразу для всего прогона.

## Тесты

- `LLM_PROVIDER=none make demo` проходит, результат валиден по контрактам.
- На 4 резюме кейса режим без LLM не даёт ни одного «Не соответствует» без доказательства кода.
- Метрики режима без LLM в `eval/report.md` отдельной строкой: это одновременно базовое решение 1 из T10.
