# T07. Сопоставление: гибрид проходов A и B

**Владельцы:** A; шаг 4 (правила) — B · **Зависит от:** T04, T05, T06 · **Критерии:** 2 (24 балла), 4 (5 баллов за связь с фрагментами), 5 (5 баллов за «не указано»)

## Цель

Для каждого требования — статус из четырёх, тип доказательства, фрагменты резюме (цитаты подставляет код), комментарий для рекрутера. Ни одного вывода без проверенного фрагмента.

## Направление сравнения (D7)

- **Основное — от вакансии к резюме, позиция HR.** Для каждого требования строго проверяем, подтверждают ли его слова кандидата. Отсюда таблица, статусы, балл и рейтинг.
- **Вспомогательное — от резюме к вакансии, позиция кандидата** (шаг 9). Какой опыт кандидата покрывает требования и что осталось за рамками. Идёт только в сильные стороны и рекомендации, **на балл не влияет**.

## Правило выбора статуса

Вопросы по порядку, первый ответ «нет» на первом вопросе останавливает:

1. Есть фрагмент резюме по теме требования? **Нет → «Не указано»** (балл нейтральный, задаём вопрос).
2. Подтверждено целиком: предмет, уровень, срок? **Да → «Соответствует»** (цитата и расчёт, если есть порог).
3. Подтверждена часть: часть срока или смежный навык? **Да → «Частично»** (в `missing` — чего не хватает).
4. Иначе → **«Не соответствует»**: в резюме есть факт, который противоречит требованию.

| Требование | Что в резюме | Статус | Почему |
|---|---|---|---|
| Высшее юридическое образование | «Образование: колледж, правоведение» | Не соответствует | Факт по теме есть и он против требования |
| Высшее юридическое образование | Раздела об образовании нет | Не указано | Молчание резюме не доказывает отсутствие диплома |
| Опыт в логистике от 3 лет | Логист 1 год 8 месяцев | Частично | Предмет совпал, срок меньше. Срок считает код |
| Права категории C | «Водитель грузового автомобиля 5 лет» | Соответствует, косвенно | Грузовик без категории C водить нельзя. Цепочка вывода обязательна |
| Работа в SolidWorks | «Проектировал в КОМПАС-3D» | Частично, смежно | Другая система того же класса |
| Знание AutoCAD | AutoCAD только в списке навыков | Соответствует, `listed_only` | Статус ставим, но это повод для вопроса |

Таблицу кладём в промпт как контрастные примеры. Все примеры — не из профессий кейса (D12).

## Шаги

### 1. Проход A — все требования вакансии одним вызовом

`src/aihr/match/prompts/pass_a.md`. Вход: фрагменты резюме `[R12] текст` (только `masked_text`), профиль кандидата коротко (места работы со стажем, посчитанным кодом), список требований с id, типом, модальностью, порогом. Выход для каждого требования:

```
requirement_id, reasoning (коротко, первым полем), status, evidence_type,
fragment_ids, inference, missing, comment, confidence
```

В промпте: рубрика статусов, контрастные примеры, явное «"Не указано" — правильный ответ, если в резюме нет фрагмента по теме», запрет цитировать (только номера), `comment` ≤ 250 символов и только о том, что есть в указанных фрагментах.

Вакансии обрабатываются параллельно.

### 2. Проверка фрагментов кодом — шлюз

- Каждый `fragment_id` существует в резюме. Несуществующие удаляются.
- Статус `match` / `partial` / `mismatch` и пустой список фрагментов после проверки → **принудительно «Не указано»** (D9). Модель физически не может поставить «не соответствует» без факта.
- `Evidence.quote` заполняет код из `Fragment.text` (D8).
- `adjacent` → статус не выше `partial`.
- `indirect` без `inference` или с `inference`, где упомянуты фрагменты не из `fragment_ids` → понижаем до `not_stated` и отправляем в проход B.

### 3. Синонимы в проходе A

В промпт для каждого требования передаём `canonical_terms` и их алиасы из T06. Модель видит, что «ОС» и «основные средства» — одно и то же.

### 4. Правила поверх LLM (B, `match/rules.py`)

`apply_rules(req, verdict, profile) -> Verdict`. Пороги проверяет код (D13):

- **Стаж (`years`).** Модель в проходе A указывает, какие места работы относятся к теме порога (через их фрагменты). Код считает объединение периодов (`tenure_for`, T05-B). `факт ≥ порог` → `match`. `0 < факт < порог` → `partial`, `partial_value = факт / порог`. Мест работы по теме нет → решение модели не меняем. В `computed` пишем расчёт: «03.2021–06.2024 = 3 г. 3 мес. ≥ 3 лет». Приближённые даты помечаем «≈».
- **Образование (`education_level`).** Сравнение по порядковой шкале из `levels.py`. Раздел образования есть, но уровня не хватает → `mismatch` с цитатой. Раздела нет → `not_stated`.
- **Язык (`language_level`).** CEFR. Уровень не указан, но язык упомянут → `partial` с вопросом. Язык не упомянут → `not_stated`.
- `decided_by = "rule"`, если правило изменило статус.

### 5. Выбор спорных требований для прохода B

В проход B идут:

- `partial`;
- `confidence < 0.7`;
- **обязательные** со статусом `mismatch` или `not_stated` (ошибка здесь дороже всего);
- `indirect`, понижённые на шаге 2.

### 6. Проход B — узкий вопрос по одному требованию

1. Поиск доказательств: `Retriever.search(текст требования, canonical_terms + aliases, k=8, section_roles по типу)` (T06-B).
2. Вызов `pass_b.md`: одно требование, найденные фрагменты, тот же формат ответа, та же рубрика.
3. Шлюз из шага 2 и правила из шага 4.
4. Слияние: если результат B прошёл шлюз — берём его. Если статусы A и B различаются → `needs_review=True`, в комментарии пометка «проверить вручную». `decided_by="pass_b"`.

### 7. Косвенные доказательства (здесь можно повозиться)

Косвенное = вывод из другого факта: «водитель грузового автомобиля» → «права категории C»; «операционная медсестра» → «знание правил асептики».

- `inference` — короткая цепочка со ссылками: «[R7] водитель грузового автомобиля 5 лет → права категории C (без них грузовик водить нельзя)».
- Код проверяет, что каждый упомянутый в `inference` id есть в `fragment_ids` и существует.
- Допустимые виды вывода перечислены в промпте: инструмент → навык, часть → целое, должность → типовые обязанности **только если они прямо названы в описании**. Должность без описания задач не доказывает конкретный навык.
- Косвенное доказательство обязательного требования → `needs_review=True`.
- В UI косвенное помечено отдельно, видна цепочка.
- Идея на потом: второй вызов-проверка «следует ли вывод из фрагментов: да / нет» (по образцу MiniCheck) только для `indirect`.

### 8. Требования без проверки по резюме

`verifiable=false` (стрессоустойчивость и т. п.) → проход A решает как обычно, почти всегда «Не указано» → вопрос для интервью в T09.

### 9. Позиция кандидата (D7)

Отдельный вызов `candidate_side.md` после итоговых вердиктов: вход — профиль кандидата и требования вакансии с их статусами. Выход — факты профиля, которые относятся к работе по вакансии, но не покрыты ни одним требованием, со ссылками на фрагменты. Результат идёт в `Report.beyond_requirements`. На балл не влияет.

## Тесты

- Шлюз: вердикт `mismatch` без фрагментов → `not_stated`; несуществующий id удаляется; `adjacent` + `match` → `partial`.
- Правила: таблица случаев стажа, образования, языка.
- Тест удаления раздела: из резюме вырезан раздел навыков → статусы навыковых требований меняются на «Не указано», а не на «Не соответствует».
- Устойчивость: перестановка разделов резюме не меняет статусы.

## Критерии готовности

- [ ] Для каждой пары резюме × вакансия кейса — полная таблица, у каждого требования статус и либо цитаты, либо «Не указано».
- [ ] 100% цитат найдено в исходном тексте.
- [ ] Macro-F1 статусов на золотом наборе (T10) выше базового решения «один промпт».
- [ ] Ошибок «Не соответствует» там, где правильно «Не указано», — 0 на золотом наборе. Это главная метрика для критерия 5.
