# T01. Загрузка документов и фрагменты

**Владелец:** B · **Зависит от:** T00 · **Критерии:** 1 (полнота фактов), 5 (4 балла за новые документы, 3 балла за плохие файлы)

## Цель

Любой файл превращается либо в `Document` с пронумерованными фрагментами и ролями разделов, либо в понятный `IngestError`. Ничего из содержимого не теряется молча: таблицы, колонтитулы и надписи тоже читаются.

## Шаги

### 1. Лестница проверок на входе

Каждая ступень либо пропускает файл дальше, либо возвращает ошибку с кодом, текстом и подсказкой.

| # | Проверка | Ошибка |
|---|---|---|
| 1 | Файл передан и не пустой (0 байт) | `E_EMPTY_FILE` |
| 2 | Размер ≤ `MAX_FILE_MB` | `E_TOO_LARGE` |
| 3 | Тип по сигнатуре, а не по расширению: `PK` + `word/document.xml` → docx, `%PDF` → pdf, декодируется как текст → txt, `{\rtf` → rtf | `E_UNSUPPORTED_TYPE` |
| 4 | Расширение совпадает с содержимым | предупреждение, если тип поддерживается; `E_TYPE_MISMATCH`, если нет |
| 5 | Сигнатура OLE (`D0 CF 11 E0`): старый `.doc` или docx с паролем | `E_ENCRYPTED` с подсказкой «снимите пароль или пересохраните в docx» |
| 6 | Архив или PDF открываются без исключений | `E_CORRUPTED` |
| 7 | После разбора есть текст (> 50 символов) | `E_NO_TEXT` с подсказкой «похоже на скан, нужен файл с текстовым слоем» |
| 8 | Документ похож на резюме / вакансию (эвристика по словарю разделов) | только предупреждение в `warnings` |

### 2. Чтение форматов

- **docx** (python-docx): обходить `document.element.body` по порядку, чтобы абзацы и таблицы шли в том порядке, как в документе. Отдельно: ячейки таблиц (резюме часто свёрстаны таблицей в две колонки), колонтитулы всех секций, надписи (`w:txbxContent` через xpath), нумерованные и маркированные списки. Свойства документа (автор, компания) не читаем — там бывают ПДн. Картинки пропускаем.
- **pdf** (pdfplumber): текст по страницам и строкам. Склеивать строки, разорванные переносом. OCR не делаем, при отсутствии текста — `E_NO_TEXT`.
- **txt**: кодировку определяет charset-normalizer (cp1251 встречается часто).
- **rtf**: `striprtf` или простой разбор. Если не получается — `E_UNSUPPORTED_TYPE` с подсказкой.
- **doc** (старый формат): `E_UNSUPPORTED_TYPE`, подсказка «пересохраните в docx».

### 3. Нормализация текста

Unicode NFKC, неразрывные пробелы → обычные, мягкие переносы удалить, переносы слов на стыке строк склеить, маркеры списков (`•`, `-`, `—`, `▪`, `*`, цифры с точкой) убрать из текста, но запомнить, что это пункт списка. Пробелы схлопнуть.

### 4. Фрагменты

- Единица — абзац, пункт списка или непустая ячейка таблицы.
- Длинный абзац (> 400 символов) режется по предложениям.
- Пустые строки отбрасываются. Короткие строки не склеиваем: в резюме это часто даты и должности.
- id: `R1, R2, …` для резюме, `V2.1, V2.2, …` для вакансии `V2`.
- Лимит: 2000 фрагментов. Больше — обрезаем с предупреждением.

### 5. Разделы и их роли

Заголовок раздела определяется по признакам: стиль Heading, жирный короткий абзац, строка капсом, строка с двоеточием на конце, совпадение со словарём. Словарь общий для всех профессий — это структура документа, а не предметная область:

| `section_role` | Примеры заголовков |
|---|---|
| `experience` | опыт работы, трудовая деятельность, места работы, work experience |
| `education` | образование, учёба, education |
| `skills` | навыки, ключевые навыки, компетенции, skills |
| `requirements` | требования, мы ждём, что нужно, кого ищем, наши ожидания, requirements |
| `nice_to_have` | будет плюсом, желательно, приветствуется, nice to have |
| `duties` | обязанности, задачи, чем предстоит заниматься, функционал, responsibilities |
| `conditions` | условия, мы предлагаем, что мы предлагаем, компенсация |
| `about` | о компании, о себе, о нас, summary |
| `contacts` | контакты, контактная информация |
| `other` | всё остальное |

Каждый фрагмент получает `section` (как написано) и `section_role`. Фрагменты до первого заголовка — `about` для вакансии, `contacts` для первых строк резюме.

### 6. Название вакансии

Первая содержательная строка или строка после «Вакансия:» / «Должность:». Записать в `Document.title`.

### 7. Изоляция ошибок

`load_document` бросает `IngestFailure(IngestError)`. `pipeline.run` ловит её для каждого файла отдельно, кладёт в `MatchResult.errors` и продолжает с остальными.

## Набор плохих файлов

`tests/fixtures/bad_files/`, на каждый файл — тест с ожидаемым кодом:

- пустой docx; файл 0 байт; файл больше лимита
- битый zip с расширением docx; картинка с расширением docx
- docx с паролем; старый .doc
- pdf-скан без текста; обрезанный pdf
- txt в cp1251; txt в utf-8 с BOM
- резюме, свёрстанное таблицей в две колонки
- резюме с контактами в колонтитуле и навыками в надписи
- вакансия сплошным текстом без заголовков
- резюме на 30 страниц
- вместо резюме загружен договор (ожидаем предупреждение, не ошибку)

## Критерии готовности

- [ ] Все 4 резюме и 3 вакансии кейса загружаются. Число фрагментов и роли разделов проверены глазами, записаны в тест как эталон.
- [ ] Каждый файл из набора плохих даёт ожидаемый код ошибки или предупреждение. Прогон с одной битой вакансией из трёх возвращает рейтинг по двум оставшимся.
- [ ] Тексты ошибок по-русски, с подсказкой, без трассировок.
- [ ] 5 вакансий с hh.ru из других профессий загружаются без ошибок, роли разделов определены.
