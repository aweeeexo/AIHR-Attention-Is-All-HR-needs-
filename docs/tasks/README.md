# Задачи: порядок, вехи, план по дням

## Распределение вдвоём (D27, с 12.11)

Две очереди идут параллельно. Модули не пересекаются (владельцы — в `CLAUDE.md` и `docs/roles/`), поэтому конфликтов в одних файлах почти не будет.

| # | Роль A — тиммейт, ML-ядро | Когда можно начинать | Роль B — владелец, платформа |
|---|---|---|---|
| 1 | **T04.** Требования вакансии: промпт, схема, проверка покрытия | сразу: нужны только вакансии и LLM | **T01.** Загрузка и фрагменты (в работе) |
| 2 | **T06, часть A.** `data/synonyms.yaml`, `normalize/synonyms.py` | сразу | **T02.** Маскирование, guard, журнал исходящих |
| 3 | **T05, часть A.** Профиль кандидата (`extract/`) | сразу на выдуманных резюме из `tests/fixtures/`; на резюме кейса — **только после T02 в `main`** | **T03.** LLM-клиент: кэш, повторы, structured output, параллельность |
| 4 | **T07, шаги 1–3.** Проход A, проверка фрагментов | после T04 и T05 | **T05, часть B.** `normalize/dates.py`, `tenure.py`, `levels.py` |
| 5 | **T10, шаги 1–3.** Разметка золотого набора — вместе с B | после T04 | **T08.** Балл и рейтинг (доводка базовой формулы из T00) |
| 6 | **T07, шаги 5–9.** Проход B, косвенные доказательства, позиция кандидата | после поиска от B (T06, часть B) | **T06, часть B + T07, шаг 4.** BM25-поиск, `match/rules.py` |
| 7 | **T09.** Отчёт рекрутеру | после T07 и T08 | **T11.** Режим без LLM |
| 8 | **T10, шаги 4–7.** Метрики, базовые решения; разделы README про ML | после T09 | **T12.** UI, README, use cases, сдача |

**Точки синхронизации:**

- **T01 в `main`** → A переходит на настоящие фрагменты с ролями разделов. Интерфейс `load_document` не меняется, код A трогать не нужно.
- **T02 в `main`** → A можно отправлять в LLM резюме кейса (только `masked_text`). До этого — только вакансии и `tests/fixtures/`.
- **T04 + T05 (A) и T05-B (B)** → веха M1: извлечение на всех документах кейса.
- **T07 (A) и T08 (B)** → веха M2: сквозной прогон со статусами, баллом и отчётом.
- `pipeline.py` и `cli.py` — модули B. A подключает свои функции, меняя только тело функций в своих модулях: сигнатуры из `contracts.md` уже вызываются из пайплайна. Нужна новая команда CLI или правка пайплайна — в PR, B смотрит.
- `contracts.py` — общий. Изменения только отдельным PR со словом `contracts` в названии, по согласию обоих.

## Если не успеваем

Режем в таком порядке, с конца:

1. Экспорт в PDF (DOCX не режем — D37).
2. Проход B для `partial` (оставляем только для must со статусами `mismatch` / `not_stated`).
3. Эмбеддинги в поиске (остаётся BM25 + словарь синонимов).
4. Позиция кандидата (`beyond_requirements`).

Не режем никогда: Docker и README (20 баллов), четыре статуса с цитатами, «не указано» по коду, рейтинг кодом, обработку плохих файлов.
