# T10. Золотой набор и метрики

**Владелец:** A; разметка — A и B вместе · **Зависит от:** T04 · **Критерии:** все технические; главный слайд защиты

## Цель

Знать качество цифрами, а не на глаз. Таблица «наше решение против базовых» на собственной разметке отличает инженерную команду от обёртки над чат-ботом и закрывает часть отраслевых баллов за «показанную ценность».

## Шаги

### 1. Требования — эталон

Для 3 вакансий кейса вручную составить список требований (`eval/golden/requirements_V{n}.json`): формулировка, must / nice, тип, порог. Удобно взять вывод T04 и исправить руками.

### 2. Статусы — эталон

4 резюме × 3 вакансии = 12 пар. Для каждой пары и каждого требования из эталона: статус, номера фрагментов-доказательств, тип доказательства (`eval/golden/verdicts_R{k}_V{n}.json`). Плюс лучшая вакансия и порядок вакансий для каждого резюме.

### 3. Согласие разметчиков

Первые 3 пары размечаем оба независимо, считаем Cohen's κ по статусам. Расхождения обсуждаем и уточняем рубрику в T07. Остальные 9 пар делим пополам. κ пишем в отчёт: это честный потолок качества.

### 4. Метрики — `make eval`

| Метрика | Что показывает | Цель |
|---|---|---|
| Полнота и точность требований | критерий 1 | ≥ 0.9 |
| Точность must / nice | критерий 1 | ≥ 0.9 |
| Macro-F1 по 4 статусам + матрица ошибок | критерий 2 | выше базовых |
| **«Не соответствует» вместо «Не указано»** | критерий 5, главный риск | 0 |
| Доля проверенных цитат | критерий 4 | 100% |
| Полнота поиска доказательств, recall@8 | T06 | ≥ 0.9 |
| Совпадение лучшей вакансии, Spearman по порядку | критерий 3 | 4 из 4 |
| Изменение балла при замене имени, пола, возраста | справедливость | ≈ 0 |
| Секунды и рубли на одно резюме | внедрение | записать |

Матрица ошибок — по требованиям в связке с вердиктами (id требований берём из эталона, сопоставляем с выводом по тексту и источнику).

### 5. Базовые решения

1. Ключевые слова: требование выполнено, если его термины есть в тексте резюме.
2. Один промпт: «сравни резюме и вакансию, верни таблицу».
3. Наше решение без шлюза фрагментов и правил.
4. Наше решение полностью.

### 6. Отчёт

`eval/report.md` с таблицей метрик, матрицей ошибок и разбором 3–5 характерных ошибок. Таблицу используем на слайде.

### 7. Регрессионный шлюз

После появления метрик каждый PR в сопоставление и извлечение показывает метрики до и после. Падение macro-F1 по статусам больше 0.03 — PR не мержим. Это стандартная практика: золотой набор, детерминированные проверки, порог.

## Дополнительный набор (если останется время)

5–10 вакансий с hh.ru других профессий и 5 синтетических резюме, сгенерированных LLM с заранее заданными ответами («требования 1, 3, 5 — явно; 2 — косвенно; 4 — частично; 6 — нет»). Метки бесплатны, ПДн нет. Проверяет работу на новых документах (критерий 5).
